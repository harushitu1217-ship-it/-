# 明景内容运营平台设计规格

日期：2026-07-12  
状态：用户已整体确认  
项目目录：`D:\软件开发\mingjing-content-platform`

## 1. 项目目标

为明景绳带工厂建设一个云端内容运营平台。运营人员可以在电脑和手机上上传绳子、织带及成品图片，填写推广要求，生成适合不同社交平台的文案、脚本、关键词和图片，并通过统一发布中心完成自动发布或人工发布。

平台通过长期发布真实、统一、可检索的行业内容，加强“明景”与绳子、织带、绳带定制、服装辅料和相关采购需求之间的公开内容关联。系统不承诺控制豆包或任何搜索平台的排名，也不采用虚假内容、关键词堆砌或其他操纵排名手段。

## 2. 已确认的产品原则

- 品牌名称统一使用“明景”。
- 采用模块化云端方案，支持电脑和手机浏览器。
- 使用左侧管理导航，登录后默认进入内容创作页。
- 视觉风格为克制、清晰、专业的企业运营后台。
- 内容创作采用混合模式：默认快速单页创作，高级选项按需展开。
- 第一版使用单管理员账号，数据结构预留多员工和角色权限。
- 人工发布第一版完整可用；自动发布窗口同时交付，官方授权后逐个平台启用。
- 豆包为默认模型，DeepSeek、通义千问和 OpenAI 可配置为备用或专项模型。
- 热点模板只提取结构和表达规律，不复制来源文章。
- 为方案 C 预留视频生成、扩大采集、搜索关联监测、客户线索和高级分析接口。

## 3. 方案选择

### 3.1 已选方案：模块化云端运营平台

前端、后端、数据存储和外部服务适配器分离。内容、热点、模型、图片和发布能力通过稳定接口协作，后续可以替换服务或增加平台，而不需要重写整个系统。

### 3.2 未选方案

- 单体快速版：初期更快，但多个模型、平台和自动发布接入后维护风险高。
- 大型采集自动化平台：首期成本和合规风险过高，不适合作为核心工具的起点。

## 4. 系统架构

```text
电脑/手机浏览器
      |
React 管理后台
      |
FastAPI 业务 API
      |
PostgreSQL + 对象存储 + 后台任务队列
      |
AI 模型适配器 / 热点来源适配器 / 图片适配器 / 发布适配器
```

### 4.1 前端

- React + TypeScript。
- 响应式管理后台，桌面端使用固定左侧导航，手机端使用可收起导航。
- 表单、草稿、生成进度、预览、编辑和发布状态提供明确反馈。
- 前端不保存模型密钥和平台敏感凭证。

### 4.2 后端

- FastAPI 提供认证、产品、内容、素材、热点、模型配置、发布任务和日志接口。
- 业务模块之间通过服务接口协作，避免路由层直接操作外部平台。
- 耗时的 AI 生成、热点采集和发布任务在后台执行，前端轮询或订阅任务状态。

### 4.3 数据和文件

- PostgreSQL 保存用户、产品、模板、内容、平台版本、任务、配置和审计记录。
- 产品原图、AI 图片和导出文件保存到对象存储；本地开发使用兼容的本地存储实现。
- 数据对象包含创建人和组织字段，第一版只启用单管理员，后续可直接扩展多用户。

### 4.4 外部适配器

- 模型适配器：豆包、DeepSeek、通义千问、OpenAI。
- 图片适配器：图片理解、封面和配图生成，可按供应商替换。
- 热点适配器：公开来源采集和人工链接导入。
- 发布适配器：每个平台独立实现能力检测、授权、发布、查询和撤销支持。

## 5. 页面与导航

### 5.1 内容创作（默认首页）

桌面端主体采用左右工作区：左侧填写图片和推广需求，右侧预览生成结果。高级设置默认收起。手机端表单和结果改为上下排列。

快速区包含：

- 上传产品图片。
- 选择或新建产品。
- 填写推广要求、目标客户和使用场景。
- 选择一个或多个目标平台。
- 一键生成六个平台内容。

高级区包含：

- 主关键词和辅助关键词。
- 内容目标、语气、篇幅和行动引导。
- 热点模板和内容类型。
- 主模型、备用模型和图片数量。
- 是否生成口播脚本、封面及配图。

结果区按平台标签切换，支持编辑、重新生成单个平台、保存草稿、复制、下载和送往发布中心。

### 5.2 其他页面

- 内容库：草稿、待审核、已完成和已发布内容。
- 热点模板：公开来源、人工导入、结构摘要、适用平台和来源时间。
- 发布中心：自动发布和人工发布在同一页面并排管理。
- 产品资料：产品图片、材质、规格、颜色、用途、优势和客户群。
- 平台账号：授权状态、支持能力、到期时间和连接测试。
- 数据分析：内容量、发布量、任务成功率和人工记录的互动数据。
- 系统设置：公司资料、品牌词、禁用表达、模型和存储配置。

## 6. 内容生成流程

1. 用户上传图片并填写本次需求。
2. 图片理解服务识别产品类别、材质、颜色、纹理和场景。
3. 用户可修正识别结果，确认后才进入生成上下文。
4. 系统读取明景公司资料、产品资料、关键词策略和选中的热点结构。
5. 豆包生成结构化基础内容；失败时按配置切换备用模型。
6. 平台转换器分别生成六个平台版本。
7. 图片服务基于原图和已确认的产品信息生成封面及配图。
8. 用户在预览区编辑并确认。
9. 内容保存到内容库，并可进入统一发布中心。

所有生成结果保存输入版本、模型、模板、来源和生成时间，便于追踪和重新生成。

## 7. 平台输出规范

- 小红书：种草标题、正文、话题标签、封面文案和配图建议。
- 抖音：短标题、发布描述、口播脚本、分镜建议和标签。
- 快手：直接的产品介绍、口播脚本、卖点和标签。
- 今日头条：行业文章、摘要、小标题、关键词和配图位置。
- 视频号：标题、简介、口播脚本、画面建议和转发文案。
- 公众号：长文章、摘要、分段标题、封面文案和正文配图。

平台规则、长度和模板作为可更新配置保存，避免写死在页面代码中。

## 8. 热点模板

### 8.1 来源

- 可公开访问的网页、榜单和趋势页面。
- 用户手工粘贴的链接、标题或案例正文。

### 8.2 处理边界

- 保存来源链接、抓取时间和可验证的来源摘要。
- 提取标题结构、开头钩子、段落节奏、内容角度和互动方式。
- 不复制原文，不伪装原创，不采集需要绕过登录或访问控制的内容。
- 采集失败不影响手工导入和内容创作。

## 9. 图片能力

- 支持多张产品图上传、排序、删除和原图保留。
- AI 识别结果必须可编辑，避免错误材质或用途进入文案。
- 可生成封面、产品宣传图和文章配图。
- 生成图片必须保留与真实产品一致的核心特征；明显失真的图片不得默认进入发布任务。
- 图片记录原图引用、提示词、生成模型、尺寸和版本。

## 10. 发布中心

### 10.1 人工发布

- 一键复制标题、正文、标签和脚本。
- 批量下载本次发布图片。
- 打开对应平台官方发布入口。
- 记录发布状态、发布时间、操作者和发布链接。

### 10.2 自动发布

- 仅使用平台官方接口和已经授权的账号。
- 支持立即发布、预约发布、取消、查询状态和失败重试。
- 每个平台显示当前是否支持自动发布，以及缺少的授权或资质。
- 发布前展示账号、内容和图片，并要求人工最终确认。
- 未获授权的平台自动降级为人工发布流程。

系统不保存平台登录密码，不绕过验证码，不模拟用户点击规避平台限制。

## 11. 权限与安全

- 第一版只有管理员角色和一个管理员账号。
- 数据表预留组织、用户、角色和资源权限字段。
- 密码采用强哈希存储；登录使用短期访问令牌和可撤销会话。
- API 密钥和平台令牌加密保存，不通过前端接口明文返回。
- 登录、配置变更、内容生成、删除和发布操作写入审计日志。
- 上传文件校验类型、大小和访问权限。

## 12. 异常处理

- 草稿自动保存，页面刷新或任务失败不会丢失已输入内容。
- AI 主模型失败时，按明确顺序切换备用模型，并记录实际使用模型。
- 外部服务失败显示可理解的原因、重试入口和人工替代方案。
- 单个平台发布失败不影响其他平台任务。
- 后台任务使用幂等键，避免重复点击造成重复发布。
- 任务状态统一为待执行、执行中、待确认、成功、失败、已取消。
- 所有失败保留日志和输入快照，支持重试。

## 13. 第一阶段范围

第一阶段交付：

- 响应式管理后台和单管理员登录。
- 公司、产品和平台资料管理。
- 图片上传、图片识别接口和可编辑识别结果。
- 六个平台内容生成、编辑、版本和草稿保存。
- 热点模板手工导入及合规的公开来源采集框架。
- 封面和配图生成接口及素材库。
- 统一发布中心，人工发布完整流程。
- 自动发布任务窗口、平台适配器接口和模拟适配器。
- 模型配置、主备切换、任务日志和基础分析。
- 本地开发环境与可迁移到云服务器的容器化配置。

第一阶段不包含：

- 绕过平台限制的自动发布。
- 大规模爬虫系统。
- 自动视频成片。
- 自动客户线索识别和 CRM。
- 承诺或操纵搜索排名。

## 14. 方案 C 扩展点

- `video_generation`：脚本转分镜、素材、配音和视频。
- `trend_collectors`：更多合规来源和调度策略。
- `search_association`：品牌和行业词公开内容监测。
- `lead_capture`：评论、私信或表单线索的授权接入。
- `advanced_analytics`：内容表现、关键词和渠道归因。

这些模块通过独立数据表、后台任务和适配器注册，不改变第一阶段核心内容模型。

## 15. 测试与验收

- 后端单元测试：平台转换、模型路由、权限、状态机和适配器。
- 后端集成测试：数据库、文件存储、任务处理和 API。
- 前端组件测试：创作表单、自动保存、预览编辑和发布状态。
- 浏览器端到端测试：登录、上传、生成、编辑、保存、人工发布和任务重试。
- 响应式检查：常见桌面宽度和手机宽度无重叠、溢出或不可操作控件。
- 安全检查：敏感配置不出现在前端、日志和仓库中。
- 发布测试：使用模拟适配器验证成功、失败、超时、重复请求和人工降级。

验收标准是运营人员不需要接触代码，即可从产品图片和需求生成六个平台素材，编辑、保存并完成人工发布准备；自动发布窗口能够准确展示能力和授权状态，并可在获得官方权限后逐个平台接入。

## 16. 部署原则

- 本地开发使用容器化服务组合。
- 云端使用 HTTPS、独立数据库、对象存储、定期备份和环境变量密钥。
- 开发、测试和生产配置分离。
- 第一阶段完成后再根据实际访问量选择云服务规格，避免过早增加固定成本。
