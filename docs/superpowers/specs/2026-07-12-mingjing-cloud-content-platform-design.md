# 明景云端内容运营平台设计

## 1. 项目目标

为明景绳带厂建设一套云端内容运营软件。运营人员上传产品照片并填写推广需求后，系统分析产品信息和公开热点，分别生成适合小红书、抖音、快手、今日头条、视频号和公众号的内容、封面与配图，并进入审核和发布流程。

系统通过持续输出真实、有用、平台风格匹配的行业内容，增强“明景”与“绳子、织带、绳带定制、服装辅料”等主题的公开内容关联。系统不承诺操控豆包或任何平台的搜索排名，不制造虚假内容，不绕过平台登录、验证码或风控。

## 2. 已确认决策

- 产品采用方案 B：云端运营工作台。
- 为方案 C 预留自动视频、爬虫集群、排名监测、客户线索和高级分析接口。
- 能使用官方发布接口的平台自动发布，其余平台采用人工确认发布。
- 先开发平台连接能力和配置页面，平台资质及密钥在开发完成后填写。
- 豆包作为主要中文内容模型，DeepSeek、通义千问和 OpenAI 可配置为备用或专项模型。
- 热点来源同时支持公开网页采集和人工粘贴链接、范文。
- 图片能力同时包括产品看图写文和营销封面、海报、配图生成。
- 软件部署到云服务器，支持电脑和手机访问及多人协作。
- 品牌统一使用“明景”，不得使用“明璟”。
- 主界面采用专业后台式布局，内容创作区保留清晰的分步操作。

## 3. 第一阶段范围

第一阶段交付可实际使用的内容生产工作台：

- 用户登录及管理员、运营、审核员权限。
- 公司资料、产品资料、关键词、禁用表达和联系方式管理。
- 产品图片上传、存储、预览和 AI 识别。
- 公开热点整理及热门链接、范文人工导入。
- 六个平台的差异化内容生成。
- 标题、正文、摘要、标签、关键词、口播稿、封面文案、图片说明和配图生成。
- 内容编辑、版本保存、审核、驳回和重新生成。
- 发布任务、定时计划、失败状态和人工发布包。
- 模型和平台接口配置页面。
- 人工录入阅读、点赞、收藏、咨询等效果数据。
- 操作日志、错误记录和基础备份机制。

第一阶段不包含绕过平台限制的自动化、不受控批量抓取、全自动视频生产、复杂 CRM 和自动排名承诺。

## 4. 系统架构

### 4.1 前端

沿用 React + TypeScript + Vite，升级为响应式运营后台。页面适配桌面浏览器和手机浏览器，主要导航包括：

- 工作台
- 内容创作
- 热点中心
- 产品与素材
- 发布任务
- 数据分析
- 团队管理
- 系统设置

### 4.2 后端

沿用 Python FastAPI，并把能力拆分为边界清晰的模块：

- 身份认证与权限
- 公司和产品资料
- 文件与素材
- 热点及模板
- AI 模型路由
- 内容生成与质量检查
- 审核工作流
- 平台连接器
- 发布任务
- 效果数据与日志

### 4.3 数据与文件

- 正式环境使用 PostgreSQL。
- 产品图、生成图和发布包使用兼容 S3 的对象存储。
- 长耗时任务通过任务队列执行，支持进度、超时和有限次数重试。
- 本地开发允许使用 SQLite 和本地文件目录，部署时通过配置切换。

### 4.4 扩展接口

以下能力必须通过统一接口接入，避免锁定某个供应商：

- `ModelProvider`：豆包、DeepSeek、通义千问、OpenAI。
- `ImageProvider`：图片理解和图片生成服务。
- `TrendCollector`：公开网页、搜索服务和人工导入来源。
- `PlatformPublisher`：六个平台的官方授权与发布实现。
- `AnalyticsProvider`：平台数据同步及后续排名监测。
- `VideoProvider`：方案 C 的自动脚本、配音、字幕和视频合成。

## 5. 核心业务流程

1. 运营人员选择已有产品或创建产品。
2. 上传一张或多张产品图片，填写目标客户、推广目标、卖点和限制要求。
3. AI 提取可能的材质、颜色、纹路、结构和使用场景，并要求用户确认不确定字段。
4. 系统从主题库、近期公开热点和人工导入模板中选择参考结构。
5. 用户选择目标平台，可一次选择全部六个平台。
6. 系统为每个平台独立生成内容，不把同一篇文章简单复制到所有平台。
7. 系统执行品牌事实、广告法敏感表达、关键词自然度、重复度和字段完整性检查。
8. 合格内容进入待审核状态；不合格内容标出原因并允许单平台重新生成。
9. 审核通过后，有官方接口的创建发布任务；无接口的生成可复制发布包并打开平台入口。
10. 发布结果和效果数据回写，用于后续选题和模板优化。

## 6. 平台内容策略

- 小红书：搜索型标题、经验分享、选购避坑、产品应用、话题标签和图片说明。
- 抖音：图文或短视频标题、开场钩子、口播稿、镜头建议、搜索关键词和标签。
- 快手：真实工厂、样品、发货、定制能力和直接询盘表达。
- 今日头条：行业知识、采购指南、材料对比、完整长文和延伸问题。
- 视频号：信任背书、应用案例、口播稿、朋友圈转发文案和私域承接。
- 公众号：目录化长文、产品百科、解决方案、案例和结尾转化信息。

每个平台保存独立模板版本、字数范围和必填字段。模板可以由管理员编辑、停用和回滚。

## 7. 热点与模板中心

- 自动采集只访问无需登录的公开页面，并设置来源白名单、访问频率和超时。
- 不绕过验证码、登录限制、付费墙和反爬措施。
- 人工导入支持链接、纯文本和范文。
- 系统提取标题结构、内容段落、受众、语气、关键词和互动方式，不直接复制原文。
- 每条模板保存来源、采集时间、平台、主题和有效期。
- 过期模板降权而非永久作为热门依据。

## 8. AI 与图片能力

- 默认文本模型为豆包，管理员可指定备用顺序。
- 不同任务可选择不同模型，例如看图、长文、改写和质量审核。
- 模型请求使用结构化输出并在后端校验字段。
- 模型不可自行补充公司资质、产能、价格、交期等事实；未知信息必须标记待确认。
- 图片生成支持平台比例、品牌色、产品主体保留、封面文字区域和无文字配图。
- 生成图片必须标明来源类型，并允许运营人员删除或重新生成。

## 9. 审核与发布

内容状态为：草稿、生成中、待审核、需修改、已通过、排期中、发布中、已发布、失败、已取消。

- 运营人员可编辑和提交审核。
- 审核员可通过、驳回并填写原因。
- 管理员可配置是否允许特定账号免审，但默认所有 AI 内容都需审核。
- 自动发布只使用官方开放接口或正式授权的服务商接口。
- 未获得资质的平台展示复制按钮、素材下载和官方创作者入口。
- 发布失败采用有限次数重试，之后进入人工处理队列，避免重复发布。

## 10. 安全与合规

- API 密钥和平台令牌只存后端，使用加密字段保存，前端仅显示掩码。
- 密码使用强哈希，登录支持会话失效和基础防暴力尝试限制。
- 文件上传校验扩展名、MIME、大小、数量和存储路径。
- 角色权限覆盖资料修改、生成、审核、发布、密钥管理和用户管理。
- 保存生成、修改、审核、发布和配置变更日志。
- 内容检查广告法高风险词、虚假保证、事实冲突和明显重复。
- 数据库、对象存储和配置定期备份，并记录恢复步骤。

## 11. 异常处理

- 主模型失败或超时时自动调用备用模型，并记录实际使用模型和费用信息。
- 单个平台生成失败不影响其他平台结果，可单独重试。
- 图片分析结论置信度不足时要求人工确认，不把猜测写进文章。
- 热点来源不可访问时跳过该来源并保留最近一次有效结果。
- 发布接口失效、令牌过期或权限不足时暂停任务并给出可执行提示。
- 所有长任务保存中间状态，页面刷新后仍能查看进度。

## 12. 测试与验收

测试范围包括：

- 登录、角色权限和密钥掩码。
- 公司资料、产品资料和禁用表达的增删改查。
- 图片上传、错误文件拒绝和产品识别确认。
- 四家模型配置、主备切换和结构化输出校验。
- 六个平台输出字段、风格差异和单平台重试。
- 热点自动来源、人工导入、来源记录和过期处理。
- 编辑、版本保存、审核、驳回和状态流转。
- 模拟发布、定时任务、令牌过期、失败重试和人工发布包。
- 桌面与手机主要页面的无重叠、无溢出和可操作性。
- 数据备份及最小恢复演练。

第一阶段验收标准：运营人员能够从产品图片和需求稳定生成六套差异化内容及配图，完成保存、编辑、审核和发布任务创建；外部 API 未配置时，系统仍能展示明确配置提示并使用可用的备用或模拟能力。

## 13. 方案 C 升级路线

第一阶段完成后，可按独立模块逐步启用：

1. 自动视频：脚本、配音、字幕、素材编排和多比例导出。
2. 热点采集集群：更多合规来源、任务调度、去重和趋势评分。
3. 平台数据同步：曝光、播放、互动、粉丝和咨询数据。
4. 搜索关联监测：定期记录公开搜索结果和品牌主题覆盖，不承诺或伪造排名。
5. 客户线索：表单、私域承接、跟进状态和内容来源归因。
6. 智能优化：根据真实表现推荐下一批选题、模板、发布时间和平台组合。

这些模块依赖本设计中的统一供应商接口、任务队列、审核流和效果数据模型，不需要重写核心内容工作台。

## 14. 实施边界

开发过程中可以按需下载开源依赖，但必须锁定版本并记录许可证。平台官方接口能否启用取决于明景后续取得的企业账号、开放平台资质和审核结果。开发环境使用模拟连接器完成流程验证，任何真实平台发布都必须在用户提供正式授权后单独启用。
